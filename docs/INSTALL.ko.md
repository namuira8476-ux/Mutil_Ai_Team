# Windows 설치와 첫 실행

## 지원 대상

0.1.15은 Windows 11 x64에서 개발·검증하는 로컬 앱입니다. x64 설치 파일 하나가 macOS·Linux·Windows ARM64에서 모두 동작하는 것은 아닙니다. 다른 OS는 별도 빌드와 CLI·PTY 검증이 필요합니다.

설치 파일: `release/AgentStudio-0.1.15-win-x64-setup.exe`. 설치 및 검증 결과는 [구현 상태](IMPLEMENTATION_STATUS.md), SHA-256은 `release/SHA256SUMS.txt`에 기록합니다. 이 개발 미리보기는 코드 서명 인증서가 없는 **서명되지 않은 설치 파일**입니다.

0.1.7부터 CLI 연결 후 중앙 대화·오른쪽 에이전트·자동화 단계에서 모델을 선택할 수 있습니다. [모델 선택 사용법](MODEL_SELECTION.ko.md). 기존 설치 위치에 업데이트하면 프로젝트·스킬·실행 기록을 유지합니다.

## 설치

1. 설치 파일을 사용할 Windows PC로 복사합니다.
2. 설치 프로그램을 실행하고 사용자 단위 설치 위치를 선택합니다.
3. 시작 메뉴에서 **Agent Studio**을 실행합니다.
4. 앱 자체는 Electron 런타임을 포함하므로 Node.js나 API 키 없이 열립니다. 모델 작업에는 사용할 CLI를 따로 설치하고 로그인해야 합니다.
5. 보안 프로그램이 출처 확인을 요구하면 전달받은 파일의 출처와 SHA-256을 확인합니다. OS 보안 기능을 끄는 방식으로 설치하지 않습니다.

## CLI 연결

필요한 CLI만 설치하면 됩니다. 앱은 PATH, 알려진 Codex 설치 위치, Windows의 `%USERPROFILE%/.local/bin/claude.exe`, `%LOCALAPPDATA%/agy/bin/agy.exe`와 `%APPDATA%/npm`을 탐색합니다. Gemini는 자동 탐색 시 Antigravity CLI(`agy`)를 우선합니다. 찾지 못하면 **설정 → 실행 경로**에서 직접 지정합니다. 이전 `gemini.cmd` 경로가 저장돼 있으면 `agy.exe` 경로로 바꾸거나 경로를 비우고 **경로 저장하고 연결 확인**을 누르세요.

| CLI | 공식 안내 | 앱에서 사용하는 방식 |
| --- | --- | --- |
| Codex | [설치·로그인](https://learn.chatgpt.com/docs/codex/cli) | `codex`, 자동 실행 `codex exec --json` |
| Claude Code | [설치·로그인](https://code.claude.com/docs/en/setup) | `claude`, 자동 실행 `claude -p --output-format stream-json` |
| Gemini 캐릭터 → Antigravity CLI | [설치·로그인](https://antigravity.google/docs/cli/install/) | `agy`, 자동 실행 `agy -p "요청" --output-format stream-json` |

각 공식 CLI를 일반 터미널에서 한 번 실행해 로그인과 초기 설정을 완료하세요. Antigravity의 Windows 공식 설치 안내는 PowerShell의 `irm https://antigravity.google/cli/install.ps1 | iex`를 제공합니다. 공식 사이트에서 설치 스크립트와 안내를 확인한 뒤 실행하고, `agy --version`, `agy` 순서로 버전과 로그인을 확인하세요. 새 PC의 로그인은 그 PC에서 진행합니다.

Google은 개인용 Gemini CLI 계정을 Antigravity로 전환했습니다. 기업용·유료 API 키 등 기존 Gemini CLI를 사용하는 환경은 명시적으로 지정한 `gemini` 경로와 기존 출력 형식도 지원합니다. [공식 전환 안내](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/). 캐릭터·공용 스킬·프로젝트 자동화의 Gemini 연결은 그대로 사용하며 실제 실행기가 `agy`로 바뀝니다.

이 앱은 로그인 비밀번호·토큰을 복사하거나 내보내지 않습니다. 연결됨은 실행파일과 버전 확인에 성공했다는 뜻이며, 유효한 로그인·충분한 계정 한도를 보장하지 않습니다.

## 첫 프로젝트

1. **새 프로젝트**를 눌러 기존 프로젝트 폴더를 선택합니다. 프로젝트를 이동하거나 복제하지 않습니다.
2. 설정에서 raw·wiki·outputs 경로를 연결합니다. 기본값은 프로젝트 안의 동명 폴더입니다. 기존 코드 폴더도 자료 탐색에서 볼 수 있습니다.
3. 부모의 모니터를 누르면 실제 CLI가 열립니다. **입력 권한 가져오기**를 누르고 CLI 내용 영역을 클릭한 뒤 입력하세요. Antigravity가 처음 여는 프로젝트의 신뢰 여부를 물으면 표시된 폴더를 확인하고 방향키와 Enter로 선택합니다.
4. **새 창으로**를 누르면 같은 세션이 별도 작업실 창으로 열립니다. 동시에 두 창이 입력하지 않도록 입력 권한이 이동합니다.
5. 자동 작업 중인 모니터는 해당 작업 로그를 엽니다. 직접 조작 세션과 자동 실행 로그는 별개입니다.

## 스킬과 자동화

- 공용 스킬에서 이름·사용 조건·작업 지침·소품을 작성합니다. 입력·결과 형식·완료 기준도 작업 지침에 적으세요.
- 원하는 CLI의 실행 버튼을 누르거나 스킬 카드를 부모 책상에 끌어다 놓습니다. 실행 중 실제 담당 부모 아래 자식이 움직입니다.
- **팀에게 맡기기**는 Codex 총괄이 앱의 `run_skill`·`get_run` 도구로 자식을 호출하도록 허용합니다. 이 두 내부 도구의 허용은 해당 실행에만 적용합니다. 총괄은 읽기 전용이며 파일 작업은 별도 담당 실행에 맡깁니다.
- 같은 프로젝트의 파일 작업은 순서대로 실행됩니다. 직접 조작 CLI가 열려 있으면 자동 작업은 그 세션이 끝날 때까지 기다립니다.
- 자동화는 기본 꺼짐입니다. **예상 동작 보기**는 모델 호출과 파일 쓰기가 없습니다. **시험 실행**은 실제 CLI 사용량이 발생하며 결과 경로는 `outputs/automation-preview/실행ID`입니다.
- 자동화를 켜도 PC가 꺼져 있거나 절전 중이면 실행되지 않습니다. **설정 → 백그라운드 유지**를 켜면 창을 닫아도 트레이에서 실행 관리자가 유지됩니다. 트레이의 **완전히 종료**는 실행 관리자를 종료합니다.
- 자동화 끄기는 다음 발생을 중지합니다. 현재 작업을 멈추려면 실행 기록에서 작업을 열고 **중지**를 누릅니다.

## 사용량과 제한

공급자가 보고한 실행 토큰만 집계합니다. 직접 조작 PTY처럼 구조화된 사용량이 없는 경우는 **미확인**입니다. 현재 컨텍스트 사용률도 이 버전에서는 미확인입니다. 계정 전체 한도와 프로젝트 토큰은 다른 항목이며, Claude의 비용은 CLI가 제공하는 추정값입니다.

Codex 계정 한도는 공식 App Server 조회를 사용합니다. Claude·Gemini 계정 전체 사용률은 안정적인 연동이 없어 미확인으로 표시하며 각 공식 CLI에서 확인하세요.

## 문제 해결

| 현상 | 확인 방법 |
| --- | --- |
| CLI 연결 필요 | 공식 CLI 설치 후 재실행. 설정에서 `.exe` 또는 공식 npm의 `.cmd` 경로 지정 |
| 로그인·권한 필요 | 해당 CLI를 직접 열어 로그인과 권한 확인 후 같은 요청 재실행 |
| 작업이 순서 대기 | 같은 프로젝트의 직접 조작 CLI나 앞선 작업 종료 확인 |
| 자동화가 실행되지 않음 | 켜짐·시간대·요일·입력 경로·백그라운드 유지·PC 절전 여부 확인 |
| 파일 자동화 순환 오류 | 결과가 자기 입력 또는 다른 규칙을 거쳐 자기 입력으로 돌아오지 않도록 경로 조정 |
| 예전 실행이 중단됨 | 결과를 확인한 뒤 재실행. 강제 종료된 CLI는 원래 세션을 자동 복구하지 않음 |
| PTY 종료 시 AttachConsole 경고 | 현재 node-pty/Windows 조합에서 종료 시 관측됨. 실행 상태와 남은 프로세스를 확인 |

설정 화면의 **데이터 폴더 열기**로 로컬 기록 위치를 확인할 수 있습니다. 기본 위치는 `%APPDATA%/agent-workroom`이며 배포 설정에 따라 이름은 앱이 보여주는 실제 위치를 우선합니다. 프로젝트 원본은 선택한 폴더에 그대로 있습니다.
