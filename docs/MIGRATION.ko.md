# 다른 PC로 작업실 옮기기

1. 기존 PC의 작업실에서 **설정 → 설정 내보내기**를 선택합니다.
2. 프로젝트 원본 폴더는 별도로 Git·복사·사용자의 동기화 방식으로 옮깁니다.
3. 새 Windows x64 PC에 작업실 설치 파일과 필요한 공식 CLI를 설치합니다.
4. CLI마다 본인 계정으로 다시 로그인합니다.
5. 작업실에서 **설정 → 가져오기**를 누르고 내보낸 JSON 파일을 선택합니다.
6. 프로젝트별로 새 PC의 실제 폴더를 선택합니다. 취소한 프로젝트는 건너뜁니다.
7. 연결 경로·스킬 버전·CLI·입출력 폴더를 확인하고 예상 동작을 봅니다.
8. 실제 시험 실행 후 필요한 자동화만 켭니다.

가져온 자동화는 항상 꺼짐으로 시작합니다. 스킬 ID가 기존 보관함과 겹치면 새 ID로 가져오고 자동화가 참조하는 버전도 함께 연결합니다. 기존 스킬을 덮어쓰지 않습니다.

| 포함 | 제외 |
| --- | --- |
| 공용 스킬과 발행 버전 | 로그인·API 키·인증 토큰 |
| 자동화 정의·고정 스킬 버전 | 살아 있는 CLI 프로세스·세션 |
| 프로젝트 이름·raw/wiki/outputs 연결 | 프로젝트 원문·코드·Wiki 실제 파일 |
| 새 PC 경로 매핑 | 이전 PC의 실행 로그·사용량 원장 |

실행 기록 전체를 보관하려면 앱을 완전히 종료한 뒤 설정의 데이터 폴더를 별도로 백업하세요. 이 백업은 기록 보관용이며, 다른 PC에서 실행 중 상태를 복구하는 기능은 아닙니다. 저장된 로그와 프롬프트에는 프로젝트 내용이 포함될 수 있으므로 본인이 관리하는 위치에 보관하세요.

앱 설치 위치와 데이터 폴더, 프로젝트 폴더는 서로 다릅니다. 새 설치 파일을 덮어 설치하는 것은 설정 가져오기와도 다릅니다. 이번 개발 미리보기에는 여러 버전 사이의 장기간 업그레이드 검증이 포함되지 않았습니다.

## 0.1.7 모델 선택값 이전

설정 내보내기에 CLI별 기본 모델과 자동화 단계별 모델도 포함됩니다. 새 PC에서 CLI를 연결한 후 모델 목록을 새로고침하고 로그인 계정이 선택한 모델을 지원하는지 확인하세요. CLI 자체의 전역 설정 파일은 내보내지 않습니다. [모델 선택 안내](MODEL_SELECTION.ko.md).
