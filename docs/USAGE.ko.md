## 0.1.15 결과 파일 찾기

완료한 답변 아래 **결과·변경 파일**에서 부모·자식 작업의 파일을 함께 찾습니다. **열기**는 문서·이미지 등 지원 파일을 기본 앱에서 열고, **파일 위치**는 탐색기에서 선택합니다. **경로 복사**와 **결과 폴더 열기**도 사용할 수 있습니다. 삭제·이동된 파일은 현재 파일 없음으로 표시합니다. 스크립트·실행파일은 자동 실행하지 않고 위치에서 확인합니다. 파일이 없는 대화는 답변을 결과로 확인하세요.

파란 호출선과 빨간 응답선은 진행 중인 팀 작업에서만 표시되며, 완료·실패·중지 후에는 사라집니다.

## 0.1.14 현재 진행 상황

작업실 중앙 위에서 실행·대기 중인 작업과 이유를 확인하세요. 마지막 CLI 출력 이후 시간이 길어도 실제 중단으로 확정하지 않습니다. 직접 조작 CLI가 프로젝트를 사용 중이면 해당 창을 확인하고 종료해야 자동 작업이 시작됩니다. **직접 조작 CLI 종료하고 대기 작업 진행** 버튼은 열린 CLI 프로세스를 종료하므로 수동 작업 중에는 먼저 마무리하세요. **대기 취소**는 아직 시작하지 않은 요청만 취소합니다.

## 0.1.13 브라우저 가로폭 맞춤

브라우저는 중앙 영역 너비를 유지합니다. 넓이가 고정된 사이트는 자동 축소하고 페이지 전체의 가로 스크롤을 제한합니다. 세로 스크롤은 웹페이지 안에서만 움직입니다. 사이트에 따라 글씨가 작아질 수 있으며 내부 표나 슬라이더는 자체 동작을 유지합니다.

## 0.1.12 내장 브라우저와 CLI 연결

프로젝트를 선택하고 중앙 위 **내장 브라우저**를 누른 뒤 웹 주소를 입력하고 **이동**을 누릅니다. 중앙 아래 메시지로 Codex에게 페이지 읽기·입력·클릭을 요청할 수 있습니다. **Codex 제어** 체크를 해제하면 AI 조작을 중지합니다. 로그인과 추가 인증은 직접 입력하세요. 현재 직접 웹 조작은 Codex만 지원하며 Claude/Gemini에는 이 브라우저 도구가 연결되어 있지 않습니다.

**설정 → Gemini 실행 경로**에서 Antigravity CLI(`agy.exe`)를 확인합니다. **경로 자동 연결**은 설치된 CLI를 찾아 저장하고, **설치 터미널 열기**는 작업실 안에서 PowerShell을 엽니다. CLI가 없을 때는 **공식 설치 실행**으로 설치할 수 있습니다. 이미 설치된 CLI는 재설치하지 않습니다. 로그인과 초기 인증은 터미널 안내를 따르세요.

검증: 실제 Codex의 페이지 읽기·한글 입력·클릭, Claude/Gemini의 브라우저 도구 미지원 응답, 임시 프로필의 제어 중지·채팅 입력·설치 터미널 입력을 확인했습니다. 새 PC에서 세 CLI를 처음 설치하는 전체 과정은 아직 검증하지 않았습니다.
# 0.1.11 한 화면 배치와 병렬 작업

세 에이전트와 입력창이 창 안에 함께 보입니다. 긴 대화는 중앙 대화 영역에서 스크롤하고, 공용 스킬 목록은 오른쪽 아래를 눌러 펼칩니다.

팀 모드에서 「카드뉴스 제목과 첫 장 문구를 독립적으로 병렬 작성해줘」처럼 요청하세요. Codex 총괄은 Gemini 우선 정책을 유지하면서 독립 작업을 먼저 시작하고 결과를 모읍니다. 작업자는 앱 전체 최대 3개이며 총괄은 별도 슬롯입니다. 같은 Gemini의 스킬 작업자도 여러 개 실행할 수 있고 오른쪽에 나란히 표시됩니다.

총괄은 run_skill의 resources.reads/writes에 정확한 경로를 선언합니다. 읽기끼리는 공유 가능하고 쓰기와 읽기/쓰기가 겹치면 순서를 지킵니다. 경로 범위를 생략한 작업은 프로젝트 단독 실행입니다. dependsOn에 지정한 선행 작업이 성공해야 후속 작업이 시작되며 실패·중지되면 후속 작업도 중지합니다. 기존 자동화 단계 순서는 유지됩니다.

경로 예약은 작업 간 충돌 조정을 위한 것으로 OS 수준의 파일 접근 격리는 아닙니다. 각 CLI는 기존 권한 설정과 지시를 따릅니다. 병렬 실행 시 토큰·사용 한도는 작업별로 소비되며 속도 향상 폭은 작업과 공급자 응답에 따라 달라집니다.

# 0.1.10 Gemini 우선 팀 모드

Codex와 「팀에게 맡기기 · Gemini 우선」을 선택하고 질문하세요. 수동 모델을 지정하지 않으면 총괄 모델은 요청 난이도에 따라 앱이 선택하고, Codex 총괄은 실제 목록에서 자식 모델을 고릅니다. 일반 작업은 Gemini Flash Low, 복잡한 작업은 Gemini Pro를 우선 고려합니다. Gemini 이외의 작업자는 선택 이유가 있어야 위임됩니다. 사용자 고정 모델과 자동화 단계의 수동 선택은 유지합니다. 작업 상세에 요청/보고 모델과 선택 이유가 남습니다.

이 정책은 팀 모드에 적용되며, CLI 직접 실행이나 기존 자동화 담당을 임의로 변경하지 않습니다. 목록 조회 실패나 적합 후보가 없으면 CLI 기본값을 사용합니다. 모델별 실제 지원과 사용량은 CLI 결과를 기준으로 확인하세요. 모델 전환 자체가 토큰/비용 절감률을 보장하지는 않습니다.

캐릭터는 작업 중 위아래로 움직이며 키보드를 칩니다. 작업 종료·응답 대기·모션 감소에서는 기존 상태 규칙을 따릅니다.

# 0.1.9 키보드가 보이는 작업 자세

모니터를 오른쪽으로 비스듬히 배치했습니다. 부모·스킬 자식 모두 드러난 키보드에 손을 올리고, 작업 중에는 그림 속 손이 작게 움직입니다. 모니터 위에 손을 겹쳐 그리던 0.1.8 방식은 교체했습니다. 파란 호출·빨간 응답 곡선과 중앙 대화 사용법은 같습니다.

## 0.1.8: 호출·응답 화살표와 타자 동작

오른쪽 책상 사이를 위아래로 잇는 포물선 화살표에 실제 부모·자식 위임 관계가 표시됩니다. **파란 화살표는 호출자에서 작업 담당자로**, **빨간 화살표는 작업 담당자에서 호출자로** 향합니다. 총괄이 Gemini에 위임하면 파란 곡선이 Codex 책상에서 Gemini 책상으로 내려가고, 빨간 응답 곡선은 Codex로 돌아갑니다. 카드 아래 상태 줄에서는 자동화의 앞 단계 담당자도 확인할 수 있습니다.

- 실행 중 파란 표시가 호출 방향으로 움직입니다. 답변을 받으면 빨간 표시가 반대 방향으로 움직입니다.
- 아직 답변이 없으면 빨간 응답 곡선은 표시하지 않습니다. 완료 후에는 화살표와 완료 문구가 최근 기록으로 남고 움직임은 멈춥니다.
- 작업 중인 부모 캐릭터와 스킬 자식에 양손 타자 동작이 나타납니다. 0.1.9에서는 모니터를 옆으로 돌려 키보드를 드러내고, 그 키보드 위의 손이 움직입니다. 단순히 CLI 모니터를 열어 둔 상태에서는 타자 동작을 표시하지 않습니다.
- 화살표를 클릭하면 해당 작업의 상세 내용이 열립니다.
- 설정의 동작 줄이기 또는 OS의 모션 감소를 켜면 애니메이션을 멈추고 색상·방향·상태 문구는 유지합니다.

화살표와 타자 동작은 작업 상태를 보여주는 시각 표현이며, 개별 네트워크 패킷이나 실제 키 입력을 재생하는 것은 아닙니다.

## 0.1.2부터: 가운데에서 대화하고, 오른쪽에서 에이전트를 확인하세요

![실제 Codex 답변과 오른쪽 에이전트 작업실](../outputs/verification/live-conversation.png)

1. 프로젝트를 선택한 뒤 **중앙 아래 메시지 입력창**에 질문을 씁니다.
2. **보내기** 또는 **Enter**를 누르면 내 질문과 에이전트 답변이 바로 위에 쌓입니다. **Shift + Enter**는 줄바꿈입니다. 한글 조합 중 Enter는 전송하지 않습니다.
3. 후속 질문에는 같은 프로젝트에서 완료한 이전 대화가 함께 전달됩니다. 답변 생성 중에도 다음 질문을 미리 입력할 수 있으며, 앞선 답변이 끝난 뒤 전송합니다.
4. **오른쪽 에이전트 작업실**에서 Codex·Claude·Gemini와 실행 중인 스킬 자식을 봅니다. 오른쪽 공용 스킬을 책상으로 끌어 놓을 수 있습니다.
5. 답변 아래 **답변 복사**, **실행 로그**, **작업 상세**로 내용을 확인합니다. 에이전트의 답변과 명령·도구 실행 로그는 분리되어 있습니다.
6. 모니터 또는 실행 로그를 열었다면 **대화로 돌아가기**로 중앙 대화창에 돌아옵니다. 화면만 돌아오는 것은 직접 조작 CLI 세션을 종료하지 않습니다.
7. **자동화** 탭에서는 중앙에서 규칙을 편집합니다. 오른쪽 에이전트 패널은 계속 표시됩니다.

0.1.3부터 앱을 열거나 작업실로 돌아오면 메시지 칸에 입력 초점이 잡힙니다. 중앙 아래 입력 상자의 빈 공간을 눌러도 입력할 수 있으며, 메시지 칸이 선택되면 테두리가 진해집니다. 화면을 이동했다 돌아와도 작성 중인 글과 커서 위치가 유지됩니다. CLI 선택 메뉴와 다른 설정 입력칸은 각각 그대로 사용할 수 있습니다.

0.1.4에서는 긴 과거 기록 때문에 입력이 멈추는 문제를 수정했습니다. 이전 버전의 답변·로그 혼합 기록은 마지막 4,000자를 미리 보고 **실행 로그**에서 전체를 확인합니다. 32,000자를 넘는 새 답변은 전체 내용을 원문 텍스트로 표시합니다. 기록과 답변 복사에는 원본 전체가 유지됩니다.

0.1.5부터 Gemini 캐릭터에 **Antigravity CLI(`agy`)**를 연결할 수 있습니다. 아래 CLI 선택에서 Gemini를 고르면 중앙 대화창으로 요청하고, 오른쪽 Gemini 모니터를 누르면 대화형 `agy`를 엽니다. 이름표의 `탐색 · agy`와 설정 화면에서 실제 연결을 확인하세요. 공용 스킬·자동화의 Gemini 단계도 같은 연결을 사용합니다. [새 PC 설치와 이전 경로 변경](INSTALL.ko.md#cli-연결).

0.1.6은 선택한 프로젝트를 Antigravity의 작업 범위로 명시합니다. 도구 권한이 필요한 작업은 **확인이 필요해요**로 표시하고 이유를 답변 아래에 안내합니다. CLI 로그인을 마친 뒤 중앙에서 새 메시지를 보내면 새 로그인 상태를 사용합니다. 이전 실패 작업은 자동으로 다시 실행되지 않습니다.

대화는 프로젝트별로 저장되어 앱을 다시 열어도 남습니다. 이전 대화는 최근 최대 12개 완료 실행, 총 24,000자 범위에서 전달하며, 개별 질문·답변도 길이 제한을 적용합니다. 이는 모든 과거 대화를 무제한 기억하거나 공급자의 CLI 세션을 그대로 재개하는 기능은 아닙니다. 0.1.1 이전 기록은 답변·로그가 함께 저장되어 중앙에서 이전 실행 기록으로 표시됩니다.

아래 3장은 0.1.1 화면을 바탕으로 만든 개념 안내 그림입니다. 0.1.2의 중앙 대화창·오른쪽 캐릭터 배치는 위 설명을 따릅니다. 그림의 **작업 시작** 버튼은 현재 중앙 입력창의 **보내기**에 해당합니다. 예시 스킬·프로젝트 이름은 직접 만든 이름과 다를 수 있습니다.

## 1. 프로젝트와 CLI 연결

![프로젝트와 CLI 연결](../outputs/agent-workroom-plan/images/06-guide-connect.png)

1. 왼쪽 **새 프로젝트**로 작업할 프로젝트의 최상위 폴더를 선택합니다. `raw` 하위 폴더만 선택하지 않습니다.
2. 오른쪽 위 톱니바퀴를 눌러 CLI 실행파일의 전체 경로를 확인한 뒤 **경로 저장하고 연결 확인**을 누릅니다. 그림의 파일명은 축약 표시입니다.
3. 작업실에서 부모 모니터를 누르고 **입력 권한 가져오기**로 CLI를 조작합니다. 공급자 안내에 따라 로그인합니다. 연결됨 표시는 실행파일·버전 확인을 뜻하며 계정 인증은 별도입니다.
4. 설정에서 프로젝트의 `raw`, `wiki`, `outputs` 상대 경로를 지정하고 **연결 저장**을 누릅니다. 그림의 원본 자료·LLM Wiki·결과 파일 표시는 각 폴더의 역할입니다.

## 2. 에이전트와 공용 스킬 실행

![에이전트와 스킬에게 일 맡기기](../outputs/agent-workroom-plan/images/07-guide-agents-skills.png)

1. 부모 모니터를 누르면 직접 조작 CLI가 열립니다. **새 창으로**는 같은 세션을 별도 앱 창에 표시합니다.
2. **공용 스킬 → 스킬 만들기**에서 이름·사용 조건·지침을 입력하고 **공용 스킬 저장**을 누릅니다.
3. 스킬 카드를 담당 CLI 책상에 끌어 놓거나 공용 스킬의 CLI별 실행 버튼을 누릅니다. 실행 중 담당 부모 아래 스킬 자식이 움직입니다.
4. 중앙 하단 입력창에서 **Codex → 팀에게 맡기기**를 선택하고 요청을 적은 다음 **보내기**를 누릅니다. 실제 위임은 요청과 모델 판단에 따라 달라집니다.

직접 조작 CLI가 열려 있으면 같은 프로젝트의 자동 작업은 기다립니다. 해당 직접 조작 세션을 종료한 뒤 자동 작업을 실행하세요.

## 3. 자동화·Wiki·사용량

![자동화하고 결과 확인하기](../outputs/agent-workroom-plan/images/08-guide-automation-results.png)

1. 프로젝트를 선택한 뒤 **이 프로젝트 자동화 → 자동화 추가**에서 실행 조건·시간·시간대를 설정합니다.
2. 담당 CLI·공용 스킬·버전·입출력 폴더를 정합니다. 순서는 최대 3단계입니다.
3. **예상 동작 보기**로 호출 없이 흐름을 살피고, **시험 실행**으로 실제 CLI 동작을 확인합니다. 시험에는 실제 사용량이 발생하고 결과는 `outputs/automation-preview/실행ID`에 저장됩니다.
4. 시험 결과를 확인한 뒤 **자동화 켜기 → 저장**을 누릅니다. PC와 실행 관리자가 켜져 있고 절전이 아니어야 합니다. 창을 닫아도 유지하려면 설정의 백그라운드 유지를 켭니다.
5. **Wiki**나 왼쪽 자료 폴더로 파일을 보고, **실행 기록**에서 작업 로그·읽은 자료·변경 파일을 확인합니다.
6. **사용량**에서 CLI·스킬·자동화별로 관측된 작업 토큰을 확인합니다. 계정 전체 한도는 별도 항목이며, 제공되지 않는 값은 미확인입니다.
