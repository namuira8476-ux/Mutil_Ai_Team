# 모델 선택 사용법 · 0.1.7

기존의 중앙 대화창과 오른쪽 연필 캐릭터 배치를 유지하면서, CLI마다 사용할 모델을 선택할 수 있습니다.

![실제 CLI 응답과 중앙·오른쪽 모델 선택기](../outputs/verification/model-selection-live.png)

위 화면은 별도 테스트 프로필에서 실제 CLI를 호출한 결과입니다. 테스트에 사용한 모델은 예시이며 사용자의 기본 모델로 저장하지 않았습니다.

## 어디에서 선택하나요?

| 위치 | 선택의 범위 | 저장 방식 |
| --- | --- | --- |
| 중앙 입력창 위 **이번 요청 모델** | 선택한 CLI로 보내는 중앙 대화 | 앱을 여는 동안 CLI별로 유지. 다시 열면 기본 모델 따르기 |
| 오른쪽 캐릭터 아래 **Codex / Claude / Gemini 기본 모델** | 해당 CLI의 새 대화·공용 스킬·자식 작업·직접 조작 CLI | 선택 즉시 이 PC에 저장. 모든 프로젝트의 기본값 |
| **자동화 → 각 단계 모델** | 해당 프로젝트 자동화의 해당 단계 | 자동화의 **저장** 버튼으로 저장 |
| **설정 → 저장할 기본 모델** | 오른쪽과 같은 CLI별 기본값 | **경로 저장하고 연결 확인**으로 함께 저장 |

**기본 모델 · …**을 고르면 저장된 기본값을 따릅니다. **CLI 기본값**은 작업실이 모델을 지정하지 않고 CLI 자체 설정을 따르게 합니다. 저장된 기본값과 다른 모델을 이번 대화에만 쓰려면 중앙에서 모델을 선택하세요. 선택은 이후 메시지에도 유지되므로, 다시 기본값을 따르려면 중앙 선택기를 **기본 모델 · …**으로 돌립니다.

목록에 없는 모델은 **모델 ID 직접 입력 → ID 작성 → 적용**으로 지정합니다. CLI가 받는 모델 ID를 넣습니다. **적용**은 선택값 확정이고, 설정 화면이나 자동화에서는 이어서 해당 화면의 저장 버튼을 눌러야 합니다.

## 카드뉴스 프로젝트 예시

1. 기존 카드뉴스 프로젝트를 선택합니다.
2. 오른쪽에서 Codex·Claude·Gemini 각각의 기본 모델을 정합니다.
3. **자동화**에서 전략·제작·검수의 담당 CLI와 공용 스킬을 고릅니다.
4. 각 단계의 모델을 고정하거나 **기본 모델**을 따르게 합니다. 담당 CLI를 바꾸면 그 단계의 모델 선택은 기본값 따르기로 초기화됩니다.
5. **예상 동작 보기**로 담당 CLI·모델·스킬을 확인하고 저장합니다. **시험 실행**은 실제 CLI를 호출하므로 해당 계정의 사용량이 발생합니다.
6. 중앙에서 **Codex → 팀에게 맡기기**로 직접 지시할 수도 있습니다. 중앙 모델은 총괄 Codex에 적용되고, 위임한 자식은 오른쪽에 저장한 각 CLI의 모델을 따릅니다. 공용 스킬 자체는 계속 세 CLI가 함께 사용합니다.

팀과 자동화는 시작 시점의 모델 선택을 보관합니다. 대기 중에 기본 설정을 바꾸더라도 이미 등록된 실행과 같은 자동화 배치의 이후 단계는 처음 선택한 모델을 사용합니다. 다음 새 작업부터 변경한 기본값이 적용됩니다. 사용자가 지시한 경우 총괄이 자식 호출에 다른 모델을 명시할 수도 있습니다.

## 실행 기록과 직접 조작 CLI

답변의 모델 배지는 **요청한 모델**입니다. **작업 상세**에서는 요청 모델과, CLI가 별도로 보고한 경우 **CLI 보고 모델**을 확인합니다. 별칭이나 CLI 기본값은 실제로 선택되는 모델이 바뀔 수 있습니다. CLI가 실제 모델을 보고하지 않으면 작업실이 추정해서 표시하지 않습니다. 업그레이드 전 실행은 **모델 미기록**으로 남습니다.

모니터로 여는 CLI에도 새 세션의 모델을 전달합니다. 다른 모델로 실행 중인 세션이 있다면 먼저 그 세션을 종료한 뒤 다시 엽니다. CLI 내부 명령으로 모델을 바꾸는 경우 작업실의 요청 모델 기록은 시작 당시 값입니다.

## 목록과 계정

- Codex는 연결된 CLI의 `app-server`에서 `model/list`를 조회합니다. [공식 프로토콜](https://learn.chatgpt.com/docs/app-server).
- Gemini 캐릭터가 `agy`로 연결돼 있으면 `agy models`의 목록을 사용하고 선택한 ID를 `--model`로 전달합니다. [Antigravity headless 사용법](https://antigravity.google/docs/cli/headless/).
- Claude는 설치된 CLI 도움말과 공식 모델 별칭을 보여줍니다. 별칭은 계정별 이용 권한을 보증하는 목록이 아닙니다. 정확한 모델 ID를 직접 입력할 수도 있습니다. [Claude 모델 설정](https://code.claude.com/docs/en/model-config).
- 기존 Gemini CLI 경로를 쓰면 모델 ID 직접 입력을 지원합니다.

**설정 → 모델 목록 새로고침**으로 목록을 다시 읽습니다. 조회 실패 이유는 설정 화면에 표시되며, 저장한 선택과 직접 입력 기능은 유지됩니다. 모델의 이용 가능 여부는 계정·조직 설정·CLI 버전에 따라 달라지며 실제 요청 결과로 확인합니다. 실패하면 실행 기록의 이유를 확인하고 다른 모델로 새 요청을 보냅니다.

작업실의 선택은 CLI 실행 인자로 전달됩니다. CLI의 전역 설정 파일이나 로그인 정보를 바꾸지 않습니다. 기존 토큰·사용량 집계는 CLI가 보고한 값으로 유지됩니다.

Codex 업데이트 후 예전에 저장한 실행파일 경로가 없어졌다면 **설정 → Codex 실행 경로**를 비우고 **경로 저장하고 연결 확인**을 누릅니다. 자동 탐색이 현재 설치 위치를 찾습니다. 이어서 모델 목록을 새로고침하세요.

## 다른 PC로 옮기기

작업실 **설정 내보내기**에는 CLI별 기본 모델과 자동화 단계별 모델도 포함됩니다. 다른 PC에서 프로젝트 폴더를 매핑해 가져오고, CLI 설치·로그인 후 모델 목록을 새로고침하세요. 이전 PC의 모델 ID가 새 계정에서도 가능한지는 확인해야 합니다. 가져온 자동화는 기존과 같이 꺼진 상태로 시작합니다. 모델 필드가 없는 구버전 내보내기도 가져올 수 있습니다.

Windows x64 설치와 프로젝트 이전은 [설치 가이드](INSTALL.ko.md), [이전 가이드](MIGRATION.ko.md)를 참고하세요.
